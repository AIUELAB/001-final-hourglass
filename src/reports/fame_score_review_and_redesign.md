# 有名人度スコア（fame_score）レビューと再設計

**作成日**: 2025-12-20
**ステータス**: Phase 1 実装完了

---

## 1. 概要

### 目的
「有名人度スコア」の算出方法を改善し、同点問題を解消する。

### 背景
現行の fame_score は手動評価の fame_tier に依存しており、91%が同一ティアに集中していた。
これにより、ランキング表示時に大量の同点が発生し、順位の意味が失われていた。

### 達成目標
- **同点削減**: ユニーク率 95%以上（旧: 54.5%）
- **上位妥当性**: Top 100 の人間レビューで違和感なし
- **自動化**: 外部API（Wikipedia Pageviews）による自動取得
- **再現性**: 再計算で同一結果

---

## 2. 現行実装の問題分析

### 2.1 スコア分布の深刻な偏り

| 指標 | ユニーク値 | 最頻値占有率 | 深刻度 |
|------|-----------|-------------|--------|
| fame_tier | 4 | 91.2%（tier 4.0） | 極度 |
| fame_score | 25 | 45.5%（6.0） | 深刻 |
| priority_score | 304 | 79.3%（49.2） | 深刻 |

### 2.2 未使用フィールド

| フィールド | 0.0の割合 | 状況 |
|-----------|----------|------|
| notoriety | 100% | 全件未設定 |
| textbook | 99.99% | ほぼ未設定 |
| award_level | 99.99% | ほぼ未設定 |

### 2.3 根本原因

1. **手動評価の未実施**: fame_tier は手動評価を想定していたが、7,668人物の評価は未実施
2. **デフォルト値の集中**: 未評価のためデフォルト tier 4.0 が91%
3. **離散スコア**: ティアベース（5段階）では差別化不可能

## 3. "有名人度"の定義

### 3.1 測定対象

- **一般認知度**: 日本の10〜50代が「名前を知っている」確率
- **継続的関心**: Wikipedia閲覧数（検索・参照頻度の代理指標）
- **文化的影響**: 教科書・辞典掲載、受賞歴（補助指標）

### 3.2 測定しないもの

- 一時的な炎上・スキャンダルによる話題性のみ
- SNSフォロワー数のみ（若年層偏重を避ける）
- 恣意的なノイズ値（乱数による差別化は信頼性を損なう）

---

## 4. 外部シグナル比較

| シグナル | 利点 | 欠点 | 取得難易度 | バイアス |
|---------|------|------|-----------|---------|
| **Wikipedia Pageviews** | 無料API、継続的関心を反映 | 古い人物に不利 | 低 | 編集者バイアス |
| Wikipedia言語版数 | 国際的認知度 | API追加呼び出し | 低 | 西洋偏重 |
| Wikipedia記事有無 | 存在証明 | 2値のみ | 低 | なし |
| Brave Search ヒット数 | リアルタイム | レート制限、コスト | 中 | 最近偏重 |
| 教科書掲載 | 歴史的評価 | 手動調査必要 | 高 | 現代人不利 |

**採用決定**: Wikipedia Pageviews API
- 無料・認証不要
- レート制限: 1 req/sec（緩い）
- 月間PVは連続値 → ユニーク率95%+達成可能

## 5. 新スコア算出式（v2）

### 5.1 計算式

```python
def calculate_fame_score_v2(monthly_pv: int, row: Dict) -> float:
    # PVスコア（対数、0-50点）
    if monthly_pv > 0:
        pv_score = min(50.0, math.log10(max(1, monthly_pv)) * 10)
    else:
        pv_score = 0.0

    # Wikipedia存在ボーナス（15点）
    wiki_exists_bonus = 15.0 if monthly_pv > 0 else 0.0

    # 受賞歴ボーナス（0-9点）
    award_bonus = min(9.0, award_level * 3)

    # 教科書掲載ボーナス（10点）
    textbook_bonus = 10.0 if textbook == "TRUE" else 0.0

    # 悪名ペナルティ（-20点）
    notoriety_penalty = -20.0 if notoriety == "TRUE" else 0.0

    # 合計（0-100点）
    return max(0.0, min(100.0,
        pv_score + wiki_exists_bonus + award_bonus + textbook_bonus + notoriety_penalty
    ))
```

### 5.2 スコア構成

| 要素 | 範囲 | 説明 |
|------|------|------|
| PVスコア | 0-50点 | log10(月間PV) × 10 |
| Wikipedia存在 | 0/15点 | ページ存在で+15 |
| 受賞歴 | 0-9点 | award_level × 3 |
| 教科書掲載 | 0/10点 | 掲載で+10 |
| 悪名ペナルティ | -20/0点 | 悪名で-20 |

### 5.3 対数スケールの効果

| 月間PV | log10 | PVスコア |
|--------|-------|---------|
| 0 | - | 0 |
| 100 | 2.0 | 20点 |
| 1,000 | 3.0 | 30点 |
| 10,000 | 4.0 | 40点 |
| 100,000 | 5.0 | 50点 |

## 6. 同点解消設計

### 6.1 タイブレーカー戦略

PVスコアが連続値のため大半は自然に差別化される。
残りの同点はepisode_idで決定的に解消。

```python
def get_ranking_key(episode):
    return (
        -fame_score_v2,        # 人物有名度（降順）
        -episode_fame_score,   # エピソード有名度（降順）
        episode_id             # 決定的タイブレーカー（昇順）
    )
```

### 6.2 score/rank分離

| フィールド | 説明 |
|-----------|------|
| fame_score_v2 | 0-100の連続値（小数点2桁） |
| wikipedia_pv | 月間ページビュー数（生データ） |
| unique_rank | タイブレーカー込み（並び順用） |

`scripts/fame_score_v2.py`
- Wikipedia Pageviews API 統合
- SQLite キャッシュ（TTL 30日、歴史人物90日）

### 7.2 キャッシュ設計

```
cache/wikipedia_pageviews.db
├── pageviews テーブル
│   ├── person_name (PRIMARY KEY)
│   ├── page_title
│   ├── monthly_views
│   ├── lang_count
│   ├── fetched_at
│   └── ttl_days
```

### 7.3 処理フロー

1. CSVからユニーク人物抽出（7,668人）
2. 各人物について:
   a. キャッシュ確認（TTL内ならスキップ）
   b. Wikipedia検索API呼び出し
   c. Pageviews API呼び出し
   d. スコア計算
   e. キャッシュ保存
3. CSVに一括反映
