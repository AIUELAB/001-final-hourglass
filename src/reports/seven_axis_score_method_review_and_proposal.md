# 7軸スコア仕様 批判的レビューと改善提案

> **作成日**: 2025-12-19
> **対象仕様**: `/Users/admin/Desktop/SEVEN_AXIS_SCORE_SPECIFICATION.md`
> **対象実装**: `backend/app/utils/score_calculator.py`

---

## 1. 概要（何を・なぜ改善するか）

### 1.1 本レビューの目的

現行の7軸スコア算出ロジックを**妥当性（validity）**と**信頼性（reliability）**の観点から批判的に評価し、「より真理（妥当性）に近い」測定方法への改善案を提案する。

### 1.2 現行システムの位置づけ

| 項目 | 現状 |
|------|------|
| 算出方式 | ルールベース（キーワードマッチング＋メタデータ参照） |
| LLM使用 | 使用しない（決定論的） |
| 外部検証 | 未実施（人手評価なし） |
| スケール | 各軸1.0-10.0、統合0-1000 |

### 1.3 改善が必要な理由

1. **構成概念妥当性の疑問**: キーワードの存在≠意味的品質
2. **外部基準の欠如**: 人手評価・利用データとの相関未検証
3. **軸間の冗長性**: 複数軸が同じ特徴を測定している可能性
4. **ゲーミング脆弱性**: キーワード詰め込みによるスコア操作が可能

### 2.2 各軸の詳細構造

#### 2.2.1 記憶性スコア

| 項目 | 内容 |
|------|------|
| **目的** | エピソードが読者の記憶に残りやすいかを評価 |

| **最大理論値** | 3.5 + 3.0 + 2.0 + 1.0 + 1.5 + 1.2 + 0.5 + 0.5 = 13.2 → 10.0（クリップ） |
| **欠損時挙動** | episode_textが空 → ベーススコア＋ペナルティで低スコア |

## 3. 妥当性/信頼性の観点での課題

### 3.1 妥当性の分類と定義

妥当性を以下の3つに分解して評価する：

| 妥当性の種類 | 定義 | 評価観点 |
|-------------|------|---------|
| **構成概念妥当性** | 測りたいものを本当に測れているか | キーワード≠概念、軸の独立性 |
| **基準関連妥当性** | 外部基準・成果指標と整合するか | 人手評価、利用データとの相関 |
| **内容的妥当性** | 指標の取りこぼし/過剰がないか | カバレッジ、重複 |

### 3.2 構成概念妥当性の課題

#### 3.2.1 キーワードベースの本質的限界

| 課題 | 具体例 | 影響 |
|------|--------|------|
| **文脈無視** | 「感動しなかった」でも「感動」で加点 | 偽陽性 |
| **否定形未考慮** | 「成功しなかった」で「成功」加点 | 偽陽性 |
| **引用内の扱い** | 「『失敗は成功の母』と言う」で両方加点 | 重複カウント |
| **多義語** | 「発見」（科学的発見 vs 気づき） | 軸間混同 |
| **比喩的使用** | 「心の革命」で「革命」加点 | 文脈不一致 |

**判断根拠**: 仕様書の算出ロジック（疑似コード）を確認した結果、すべてのキーワードマッチングは単純な部分文字列検索（`if kw in episode_text`）で実装されており、文脈を考慮する仕組みがない。

#### 3.2.2 軸間の相関・冗長性

同じキーワードまたは類似概念が複数軸で使用されている：

| 共有キーワード/概念 | 使用される軸 | 問題 |
|-------------------|-------------|------|
| 「感動」「希望」「勇気」等 | 共感性、ストーリー品質 | 同じ特徴を二重測定 |
| 「史上初」「世界初」 | 記憶性、意外性 | 記憶に残る≒意外 |
| 「達成」「成功」「記録」 | 記憶性、教育的価値、事実密度 | 事実≒記憶≒教訓？ |
| 引用（「」）の存在 | 共感性、生成品質、ストーリー品質、事実密度 | 4軸で加点 |
| テキスト長 | 生成品質、ストーリー品質、事実密度 | 3軸で評価 |

**検証方法（提案）**: 実データで7軸間の相関行列を算出し、r > 0.7の軸ペアを特定する。

#### 3.2.3 構成概念の定義曖昧性

| 軸 | 定義の曖昧さ | 影響 |
|-----|-------------|------|
| 記憶性 | 「記憶に残る」の操作的定義がない | 何をもって記憶性とするか不明 |
| 共感性 | 「感情的共鳴」≠「感情キーワードの存在」 | 実際の共感を測定していない |
| 意外性 | 読者にとっての意外性 vs テキスト内の表現 | 主観的概念を客観的に測定 |
| ストーリー品質 | 「起承転結」の評価が不在 | 構成評価と言いつつキーワード計数 |

### 3.3 基準関連妥当性の課題

#### 3.3.1 外部基準の完全欠如

| 検証項目 | 現状 | 必要な対応 |
|---------|------|-----------|
| 人手評価との相関 | **未実施** | 評価データセット構築 |
| 読者エンゲージメント | **未計測** | 閲覧時間、共有数等の収集 |
| ドメイン専門家評価 | **未実施** | 専門家レビュープロセス |
| A/Bテスト | **未実施** | スコア別の利用比較 |

**判断根拠**: 仕様書の「12. テスト状況と追加テスト観点」に「テストファイル: なし」と明記されている。

#### 3.3.2 目的変数の不在

「良いエピソード」を定義する明確な基準がない：

- スコアが高いエピソードは本当に「良い」のか？
- 「良い」とは何か？（教育効果？エンターテインメント性？事実正確性？）
- 7軸の重み付けの根拠は？

### 3.4 内容的妥当性の課題

#### 3.4.1 カバレッジ不足（測定されていない品質次元）

| 欠落している観点 | 説明 | 重要度 |
|-----------------|------|--------|
| **文体の洗練度** | 語彙多様性、文法複雑度、文体一貫性 | 高 |
| **論理構成** | 因果関係の明確さ、時系列の論理性 | 高 |
| **独自性** | 他エピソードとの差別化、新規性 | 中 |
| **正確性** | 事実誤認の有無、情報源の信頼性 | 高 |
| **読みやすさ** | Flesch-Kincaid的な指標 | 中 |
| **感情の深度** | 表面的言及 vs 深い描写 | 中 |

#### 3.4.2 過剰カバー（重複評価）

| 重複している特徴 | 評価される軸 | 問題 |
|-----------------|-------------|------|
| テキスト長 | 生成品質、ストーリー品質、事実密度 | 長いだけで3軸上昇 |
| 引用の存在 | 共感性、生成品質、ストーリー品質、事実密度 | 「」があるだけで4軸上昇 |
| 数値の存在 | 記憶性、教育的価値、ストーリー品質、事実密度 | 数字があるだけで4軸上昇 |

### 3.5 信頼性の課題

#### 3.5.1 内的一貫性

| 問題 | 詳細 |
|------|------|
| ベーススコアの不統一 | 軸によって3.0〜3.5とばらつき |
| 加点上限の恣意性 | なぜ+2.0上限？+2.5上限？根拠不明 |
| 減点の非対称性 | 加点機会が多く、減点は限定的 |

#### 3.5.2 テスト-再テスト信頼性

| 問題 | 詳細 |
|------|------|
| 言い換え不安定性 | 同内容で表現を変えるとスコア変動 |
| 語順影響 | キーワードの位置は評価されない |

### 3.6 ゲーミング耐性の課題

| ゲーミング手法 | 容易さ | 対策状況 |
|---------------|--------|---------|
| キーワード詰め込み | **容易** | 上限設定あるが下限での操作は容易 |
| フォーマット準拠 | **容易** | 「あなたと同じ」で+0.8確定 |
| 引用追加 | **容易** | 「」を入れるだけで複数軸上昇 |
| 数値追加 | **容易** | 任意の数字で複数軸上昇 |
| 文字数調整 | **容易** | 220-320文字に調整で最高加点 |

### 3.7 ドメイン依存の課題

#### 3.7.1 カテゴリバイアス

| 有利なカテゴリ | 理由 | 不利なカテゴリ |
|--------------|------|--------------|
| スポーツ | 記録・数値が豊富、意外性カテゴリ補正+0.8 | 芸術・文化 |
| 科学・技術 | 事実キーワード（発明・発見）、教育的価値+1.5 | 日常生活 |
| ビジネス・経済 | 数値データが豊富 | 思想・哲学（抽象的） |

#### 3.7.2 言語依存

- 全キーワードが日本語
- 英語・他言語への拡張不可
- 日本語特有の表現（「〜ような」「〜といった」）に依存

## 4. 改善案（優先度付き：短期/中期/長期）

### 4.1 短期改善（1〜3日）

#### 4.1.1 否定形・文脈パターンの除外

| ねらい | 偽陽性の削減（構成概念妥当性向上） |
|--------|--------------------------------|
| 変更点 | キーワードマッチング前に否定パターンを除外 |
| 実装案 | `if kw in text and not re.search(f"{kw}(しな|でき|ない)", text)` |
| 期待効果 | 偽陽性率5-10%削減（推定） |
| リスク | 処理時間微増、正当な否定表現の過剰除外 |
| 検証方法 | 手動サンプリング50件で偽陽性率比較 |
| コスト | 開発0.5日、検証0.5日 |

#### 4.1.2 軸間相関の測定・可視化

| ねらい | 冗長性の定量化（内容的妥当性の検証） |
|--------|--------------------------------|
| 変更点 | 7軸×7軸の相関行列を算出・レポート化 |
| 実装案 | 既存データでPearson/Spearman相関を計算 |
| 期待効果 | r > 0.7の軸ペアを特定し、統合・分離の判断材料 |
| リスク | 低（分析のみ） |
| 検証方法 | 全エピソードデータで相関分析 |
| コスト | 開発0.5日 |

#### 4.1.3 テキスト長正規化の導入

| ねらい | 長いテキストへのバイアス軽減 |
|--------|--------------------------|
| 変更点 | キーワードカウントをテキスト長で正規化 |
| 実装案 | `normalized_count = count / (len(text) / 200)` |
| 期待効果 | 文字数とスコアの相関低下 |
| リスク | 既存スコア分布の変化 |
| 検証方法 | 変更前後のスコア分布比較 |
| コスト | 開発0.5日、検証0.5日 |

#### 4.1.4 重複キーワードカウント制限

| ねらい | 同一キーワード連呼によるゲーミング防止 |
|--------|----------------------------------|
| 変更点 | 同一キーワードは1回のみカウント（set化） |
| 実装案 | `count = len(set(kw for kw in keywords if kw in text))` |
| 期待効果 | ゲーミング耐性向上 |
| リスク | 低（正当な繰り返しも1回に） |
| 検証方法 | キーワード重複頻度の分析 |
| コスト | 開発0.5日 |

### 4.2 中期改善（1〜4週）

#### 4.2.1 人手評価データセット構築

| ねらい | 基準関連妥当性の確立 |
|--------|-------------------|
| 変更点 | 専門家による200件の評価データ作成 |
| 実装案 | 7軸それぞれを5段階で人手評価、評価者間一致度（κ係数）測定 |
| 期待効果 | ルールスコアと人手評価の相関算出が可能に |
| リスク | 評価者確保、評価基準の統一 |
| 検証方法 | κ > 0.6を目標とした評価者訓練 |
| コスト | 設計1週、実施2週、分析1週 |

**評価ガイドライン案**:

```markdown
## 記憶性評価基準（人手用）
5: 数年後も思い出せるほど印象的
4: 数日後も記憶に残る
3: 読後しばらく覚えている
2: 読んだことは覚えているが詳細は曖昧
1: すぐに忘れる
```

#### 4.2.2 LLM活用による意味的評価の試験導入

| ねらい | キーワードの文脈評価（構成概念妥当性向上） |
|--------|--------------------------------------|
| 変更点 | 7軸のうち1-2軸でLLM評価を並行実施 |
| 実装案 | Claude API で「このエピソードの共感性を1-10で評価」 |
| 期待効果 | 文脈を考慮した評価が可能に |
| リスク | コスト増、応答時間増、LLM出力の揺れ |
| 検証方法 | ルールベース vs LLM vs 人手の三者相関 |
| コスト | 設計1週、実装1週、検証2週 |

#### 4.2.3 軸の再設計（重複排除・新軸追加）

| ねらい | 内容的妥当性の向上 |
|--------|------------------|
| 変更点 | 高相関軸の統合、欠落観点の追加 |
| 候補案 | 共感性＋ストーリー品質→「感情的品質」に統合 |
|        | 新軸「論理構成」「正確性」の追加検討 |
| 期待効果 | 軸の独立性向上、評価の網羅性向上 |
| リスク | 既存データとの互換性、再計算コスト |

### 7.2 すぐ始める最小ステップ（次に何をするか）

#### Step 1: 相関分析の実施（所要時間: 2-4時間）

```python
# 実行コマンド案
import pandas as pd
import numpy as np

# マスターCSV読み込み
df = pd.read_csv("preserved/data/MASTER_EPISODES_CURRENT.csv", encoding="utf-8-sig")

# 7軸の列を抽出
axis_columns = [
    "記憶性スコア", "共感性スコア", "意外性スコア",
    "生成品質スコア", "教育的価値", "ストーリー品質", "事実密度"
]
axis_df = df[axis_columns].dropna()

# 相関行列
corr_matrix = axis_df.corr(method="spearman")
print(corr_matrix)

# 高相関ペアの抽出
for i in range(len(axis_columns)):
    for j in range(i+1, len(axis_columns)):
        r = corr_matrix.iloc[i, j]
        if abs(r) > 0.7:
            print(f"高相関: {axis_columns[i]} <-> {axis_columns[j]}: r={r:.3f}")
```

#### Step 2: 結果に基づく次のアクション決定

- 高相関ペアあり → 軸の統合・再設計を検討
- 高相関ペアなし → 人手評価データセット構築に着手

### 8.2 相関分析の結果

```
高相関ペア（|r| >= 0.7）:
  記憶性 <-> 生成品質: r = 0.887
  共感性 <-> 意外性: r = 0.803
  記憶性 <-> 意外性: r = 0.770
  共感性 <-> 生成品質: r = 0.746
  意外性 <-> 生成品質: r = 0.765
```

**発見**: 5組の高相関ペアが存在。特に「記憶性↔生成品質」(r=0.887)は非常に高く、同じ特徴を測定している可能性が高い。

### 8.3 重大な発見：CSVスコアとルールベース算出の乖離

検証中に以下の根本的な問題が判明しました。

| 項目 | CSVスコア | ルールベース算出 |
|------|----------|----------------|
| 生成元 | LLM（エピソード生成時に主観採点） | score_calculator.py |
| 平均値 | 7.5〜8.1（高め） | 2.0〜5.0（低め） |
| 採点方式 | 主観的・文脈考慮 | キーワードカウント・ルールベース |
| スケール | 10点満点（甘め） | 10点満点（厳しめ） |

**結論**: CSVの7軸スコアは、エピソード生成時にLLMが「記憶に残りやすさ」等を主観的に採点した値であり、`score_calculator.py`のルールベース算出とは**異なるスコア体系**です。

### 8.4 改善の妥当性評価

| 改善項目 | 技術的妥当性 | 備考 |
|---------|------------|------|
| 否定形除外 | ✅ 正しい | 「成功しなかった」を正しく除外 |
| 重複制限 | ✅ 正しい | 同一KW複数カウントを防止 |
| テキスト長正規化 | ✅ 正しい | 長文バイアスを軽減 |

### 8.5 今後の方針

1. **現行改善は維持**: `count_keywords_v3()`は技術的に正しい改善
2. **CSVスコアは別管理**: LLM採点スコアとルールベーススコアは別物として扱う
3. **用途の明確化**:
   - CSVスコア → ユーザー向け表示用（既存値を維持）
   - ルールベーススコア → 分析・フィルタリング用
